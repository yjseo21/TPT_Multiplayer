# Bug hunt, 3 November 2026

A new tool, `tpt-bughunt` (`tests/multiplayer/BugHunt.cpp`), runs the room's
physics through every element, combination, player action and setting. It
checks the simulation's own bookkeeping after every tick:

- particles have a valid type, finite motion, a temperature from 0 to 9999 K,
  and a position on the screen;
- element counts and the particle count match the particles that exist
  (placing a stickman and several elements depend on them);
- stickmen and fighters agree with their particles, with no ghosts;
- the particle maps name the right type;
- air values are finite.

A sample of scenes must also continue exactly from a snapshot (what a joining
player gets) and survive a save round trip. Scenes are rendered, so every
element's graphics function runs too.

Modes:

| Mode | What it covers |
| --- | --- |
| `pairs` | Every element against every other (37,636 scenes): hot, near absolute zero, under pressure, and with a spark at the seam. |
| `actions` | Console `set` of every property of every element, to ordinary and extreme values, cold and hot. |
| `tools` | Every tool: heat, air, gravity, walls, decoration, element tools. Each runs every action and brush, at strengths 1–1000, with replace modes, on every element. |
| `paste` | Every element's scene pasted as a stamp onto busy scenes, overlapping them and partly off the screen. |
| `restart` | An autosave loaded into a new room, compared field by field: particles, settings, walls and air. |
| `settings` | Every element under every room setting (edges, gravity, air modes, Newtonian gravity, heat modes and so on). |
| `stickmen` | All four room stickmen hold and use every element while walking, jumping and crouching. |
| `signs` | Sign text with formatting and broken forms, at every edge of the screen, plus sign buttons. |
| `digests` | A fingerprint of every pair scene under rotating settings, for comparing builds. |
| `chaos` | Random scenes and random player commands of every kind for long runs. |

Usage: `tpt-bughunt MODE [--shard K --of N] [--ticks T]`. For `chaos`,
`BUGHUNT_RUN=N` replays one run and logs its commands, and `BUGHUNT_SEED`
shifts the seeds.

Every mode ran in release builds, and under AddressSanitizer and UBSan.
`digests` agreed exactly across Linux GCC, Linux clang and Windows (MinGW,
UCRT) on all 37,636 scenes.

## Bugs fixed

1. **Sparking a conductor left element counts wrong.** `create_part(SPRK)`
   changed the type directly, so the conductor stayed overcounted and SPRK
   was undercounted.
2. **Tungsten-filled BRMT melting** briefly became TUNG without moving its
   count from BRMT.
3. **Heating past 9999 K, and BREC cooling below 0 K under vacuum.** Affected:
   CAUS and ACID dissolving things, BASE, BREC, GLAS, H2 (three places), NBLE
   fusion.
4. **WARP heated itself to 10000 K**, one degree over the maximum.
5. **Console `set` and the property tool accepted temperatures outside
   0–9999 K.** They now clamp them.
6. **Console `set` and the property tool accepted positions off the screen.**
   Rounding such a position to an int is undefined behaviour. Positions must
   now be on the screen, and velocities are capped.
7. **Resetting sparks** (game and room) left element counts and the particle
   map wrong. A spark whose ctype was 0 became a dead particle that still held
   its slot. Both now use one `Simulation::ResetSparks`.
8. **Loading a save allocated each fighter twice.** The first slot leaked as a
   ghost, so only half of a save's fighters loaded. This affected pastes,
   stamps and room restarts.
9. **A fighter that couldn't be allocated during a load** was left as a
   counted, mapped dead particle. It is now removed properly.
10. **Freeing a fighter with no fighter slot** (`tmp = -1`) read `fighters[255]`,
    past the end of a 100-entry array.
11. **Room stickman keys were sent only when they changed.** After the room
    reset a stickman's keys (placing it again, respawning, resynchronizing),
    pressing a key did nothing.
12. **A room stickman kept walking forever** when the game lost focus or the
    player switched to their own canvas while holding an arrow key.
13. **Stickman commands queued behind strokes.** While a player drew, steering
    lagged up to two seconds. Once the queue was full, a key release was
    dropped and the stickman walked on.
14. **Signed integer overflow** in 24 element files when `life`/`tmp` hold
    extreme values (possible from the console). That's undefined behaviour, so
    each compiler may compute something different. Multiplayer builds now use
    `-fwrapv` (clang-cl: `/clang:-fwrapv`).
15. **A sparked tungsten wire near 0 K** could fall below absolute zero.
16. **Crash: BASE with negative life.** Its boiling chance drew from an empty
    range, a modulo by zero. Any room player could crash the server with the
    property tool. Its cooling also divided by its life.
17. **TRON's graphics**: a negative life or tiny `tmp2` gave an alpha far
    outside an int.
18. **EMP truncated positions instead of rounding them.** Type changes landed
    in the neighbouring pixel's map entry and left a stale SPRK entry. Its
    centre-exclusion test also used the particle's position instead of the
    offset.
19. **Setting a fighter's `tmp`** (its fighter-table entry) through the console
    or property tool leaked the fighter, or shared one between two particles.
    The change is now ignored.
20. **PTNM catalysis heated past 9999 K.**
21. **O2 combustion heated past 9999 K.**
22. **POLO heated past 9999 K** when averaging hot neighbours.

## Found earlier in this release

- Element counts doubled after edits in a fresh, cleared or paused room.
- Fighters of players 3 and 4 lost their player in portals.
- Placing a stickman held in a portal failed or duplicated it.

See `PERFORMANCE_2026-11-02.md`, "Heavy rooms and four stickmen (1.0.5)".

## Not bugs

These were checked and left alone:
- **Runtime `flags`** aren't saved: by design.
- **Portal `life`** is a cosmetic orbit seed, saved as 16 bits.
- **Pressure and velocity** are rounded in saves: the save format's
  resolution.
- **SOAP `tmp2`** is a link only when the ctype link bit is set.
- **The server does ping its clients** every 20 s.

The pinned determinism fingerprint is now `3ef3ab781baff060`, computed alike
by Linux GCC, Linux clang and Windows UCRT.

## Drawing with Shift and Ctrl in rooms (4 November)

Reported: Shift lines (and other modifier drawing) were cut short with "This
stroke is too large for the room to keep up; part of it was skipped."

1. **Line mode sent a full line on every mouse move.** While Shift is held the
   game calls the tool's drag at each move, which only wind uses. In a room each
   was a command charged as a line from the start to the cursor: a big brush
   used up the editing budget (or was refused outright) before the button was
   released, and the real line was then cut. Drags are now sent only for wind,
   and the release click only for the fighter tool.
2. **The editing budget was far stricter than needed.** It was 3 million brush
   cells a second per player; a cell takes about 3 ns on the server, so that is
   under 1% of a core. A full-width line with a radius-50 brush (6 million)
   could never go through. It is now 20 million (about 60 ms of server time a
   second), with the per-command limit unchanged, so no single command holds up
   a tick for more than about 3 ms.
3. **A Shift line, Ctrl box or fill was cut like a freehand drag.** These now go
   whole and are paced out; the largest possible line (full width, radius 200)
   takes about five seconds. Only freehand drags beyond two seconds of work are
   still trimmed, as before.
4. **Walls were charged per pixel**, about 16 times what they cost: walls work on
   4x4 cells.
5. **Wind was charged and split as a line.** It stamps its brush once and
   pushes along the line, so splitting changed the push. It is now one command.
