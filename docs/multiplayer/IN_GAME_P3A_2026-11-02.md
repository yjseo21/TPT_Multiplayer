# TPT multiplayer: the real game joins a room (P3a)

**Engineering handoff, 2 November 2026.** First slice of phase P3 of
`IN_GAME_MULTIPLAYER_PLAN.md`.

## What works

```sh
export TPT_ROOM_TOKEN='room password'        # TPT_ADMIN_TOKEN too, for room controls
./powder join:ws://127.0.0.1:34403 name:Alice # remote rooms need wss://
```

- The normal game (`powder`, full upstream interface) connects with local
  simulation and shows the room's world through its own renderer, HUD and
  debug overlays. The room's status line sits under the FPS line.
- **Ctrl+Shift+M** switches between the room and your own canvas. Your own
  world stays in memory unchanged, and the room keeps running and stays in
  sync while you are away from it. Opening or loading a save switches to your
  own canvas first.
- Drawing goes to the room. `DrawPoints`, `DrawLine`, `DrawRect`,
  `DrawFill`, `ToolClick` and `ToolDrag` become commands replayed through the
  same `Tool` methods on every machine. That covers every element, wall and
  simulation tool, ellipse (including the perfect-circle setting), rectangle
  and triangle brushes with separate X/Y radius up to 200, tool strength,
  shift/ctrl/alt behaviour and replace mode.
- Strokes too large for one command are split. An outgoing queue paces commands
  to the server's editing budget (3M brush cells/s, 120 commands/s), so a huge
  stroke arrives progressively. Beyond about 2 s of queued work the rest of the
  stroke is skipped, with a notice. Pause, frame step and clear are room
  commands, admin only, through the same queue in order.
- Not yet available in rooms, each with a clear notice: undo/redo, pasting
  saves and stamps, cut (copy works), air/spark/ambient-heat resets, gravity,
  air and edge modes, Newtonian gravity, sign buttons, custom bitmap brushes,
  interface tools (sign, property, decoration), saving the room's world, and
  console commands that change the world. Stickman keys only ever act on your
  own world.

## Bugs found by running the real game

1. **Floating-point mode.** The game runs physics with x86 denormals flushed to
   zero (`X86KillDenormals`, enabled on every SSE build). The server and tools
   did not, so the game diverged from the server in air state after about 3 s.
   Earlier cross-platform runs were consistent only because no participant used
   the game's mode. Fix: `World::Advance` and `World::Apply` set the same mode
   (`FloatingPoint.cpp`), so rooms behave exactly like single-player physics on
   every participant. The cross-platform run passed again afterwards: Linux
   server, Windows replica and Windows local client, 2 minutes, 41 edits,
   118–121 fingerprints each, 0 divergence.
2. **Large strokes dropped the connection** (64 unconfirmed edits). Fixed by
   the paced queue.
3. **Status said SYNCHRONIZING forever in the game**, because status assumed a
   published picture, which only `tpt-remote` provides. Local-simulation status
   and pause now come from the replica.
4. **Cursor radius** above 16 was rejected by the server; the cursor is now clamped.
5. **Interface state on the simulation.** Replace-mode settings, stickman input
   and stickman respawn live on the simulation in upstream code. They now
   always use your own world, so they can never change the room's replica.

## Tests

- `multiplayer-game-room` (`tests/multiplayer/game_room_test.py`): runs the
  real `powder` headless (SDL dummy video) with `join:` and
  `TPT_MP_AUTOMATION`. The automation calls the controller's own input entry
  points: shaped brushes, rectangle, wall line, triangle, a radius-200 stroke
  that must be split and trimmed, a refused action, drawing on your own canvas,
  then pause and step. Checks: 0 resyncs, fingerprints verified, edits
  identical to a `tpt-remote` watcher in the same room, own canvas changed,
  status PAUSED. Passed 5 of 5 runs in a row, and in the full suite.
- Core tests cover separate radii, all brush shapes, the unchanged record
  format for round brushes, the radius limit and stroke splitting.
- Full suite: 18 pass, 0 fail, 1 skip (impaired-network needs root).
